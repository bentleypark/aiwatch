2026-07-09 lint(#967): added `scripts/lint-decision-graph.mjs` (+ `npm run lint:graph`, wired into the `memory-lint` skill as check 6). The 4th strategy-review dogfood run flagged its own weakest claim — the nine `advances::` slice edges are a hand reading. Calling that "not machine-verifiable" was imprecise: it conflates a **dead edge** (points at a closed issue / a PR / nothing), a **double claim**, a **wrong claim** (real open issue that doesn't advance the initiative) and a **missing claim**. The first two are ordinary structural checks; only the last two are judgement. So the lint hard-fails on edge grammar, dead edges, duplicate claims and dangling wikilinks, and reports *unclaimed candidates* (open `area:biz`/`area:marketing` issues no initiative claims) while **exiting 0** — a lint that adjudicates judgement manufactures false confidence. Same structural-vs-judgement split `index.md` already draws for the OKF bundle. Bugs found while building it: (1) the first hand-run of the liveness check compared `gh`'s lowercase `open` against `'OPEN'` and reported nine false failures — pinned by a test; (2) `npm run lint:graph --github` silently swallows the flag (npm eats it) and runs the offline subset, passing while skipping every liveness check — npm arg behaviour, not unit-testable, so it is mitigated by docs alone (the `--` form is now mandatory). Review then found three more, all pinned by tests: a bare `catch {}` around `gh api` treated a network loss / expired token / 403 rate-limit identically to a 404, so ONE blip would report every `advances::` edge dead and exit 1 (now `classifyGhError` — only a real 404 is a dead edge; anything else aborts the liveness pass with exit 2, "a tool failure, not a graph failure"); `#(\d+)` silently truncated the bundle's live `constrains:: #842-B` to `#842`, an unrelated real issue (ids are captured whole now, and an `advances::` edge with a non-numeric id is a loud `edge-undereferenceable` finding rather than a wrong lookup); and a backticked *example* edge — `` `bounds:: #862` ``, which the vocabulary doc writes as a don't-do-this illustration — parsed as a real edge, so code spans and fences are stripped before matching. Object-side grammar (`bounds`/`supersedes` must target a decision PAGE; `advances` must target an issue) is enforced too — the doc stated those rules and the lint checked only half of one. Deliberately NOT done: moving membership onto issues as `initiative:*` labels. That is the structurally correct home for an `advances` edge (its subject IS the issue) and would make the slice list generated rather than hand-maintained, but the #917 vocabulary was corrected twice in one session and has not survived a cross-session use; layering a board-wide convention on an unproven design repeats that mistake. Revisit when membership actually drives a recommendation — the 2026-07-09 do-next came from urgency labels and the decision graph, not the slice lists.

2026-07-10 fix(#969 readability + windows): two output defects. (1) A brief printed `delivered:: #778 · #777 · #805 · #566 · #936` and expected a reader to know what shipped.
