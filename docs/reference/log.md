2026-07-09 lint(#917): the seeded pages drifted from the vocabulary — 6 of 7 typed links were off-spec (invented inverse names `expressed-as`/`constrained-by`, `bounds`/`evidences` written backwards from the Decision page, an out-of-spec Decision→Decision `constrains`). Root cause: the table named each relation in ONE direction, but a wiki page naturally states edges from its OWN side, and the `Constraint`/`Metric` entities it referenced had no pages to point at. Fixed by amending the vocabulary, not the prose: added the three **writing rules** (typed `rel::` only on the SUBJECT's page · the object end takes a plain untyped backlink, no inverse names · an object may be a `[[wikilink]]` or a stable external id like `#803`), widened `constrains` to allow a Decision object + `evidences` to allow an evidence page as subject, and created the four missing `type:constraint` memory nodes (solo_capacity / kr_network_separation / neutrality_moat / free_tier_budget) that strategy-review step 1 already instructed the reader to load. Follow-up in the same pass: `constraint_free_tier_budget` initially pointed its `bounds::` edges at PR numbers (#862/#842-B/#920) — architecture decisions that were never normalized into pages. Rather than widen `bounds` to accept an Issue object (which would have let every future architecture decision drain out of the log into issue numbers), the two decisions were written up (`decision_edge_ssr_for_public_pages`, `decision_wae_over_kv_for_traffic_counters`) and rule 3 now states the invariant explicitly: **an edge leaves the wiki only when the entity type has no page by design — a Decision always has a page.**
